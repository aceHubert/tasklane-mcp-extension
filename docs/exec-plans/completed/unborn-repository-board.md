## 目标

已经 git init、尚无任何提交的仓库可以通过 open_tasklane 注册和打开项目看板，
管理任务并保持仓库隔离。实际创建任务分支/worktree 时才要求首次提交和可用基线。

## 范围

- 包含：仓库身份与执行条件解耦、空仓库基线校验、Git 降级说明、原生打开协议验证、
  目录选择器检测、必要帮助文本、英文技能与插件构建。
- 不包含：自动初始化或提交用户仓库、修改真实任务数据、自动启动真实 Agent、
  非 Git 项目支持、存储版本迁移或改变已有有效基线规则。

## 背景

- 相关代码：packages/core/src/git.ts、engine.ts、extension/src/widget.mjs。
- 原 identifyRepo 校验 HEAD，导致空仓库在身份识别阶段即被拒绝。
- 注册记录沿用 repoKey、repo、baseBranch；没有持久化“空仓库”状态。

## 风险

- 空仓库接受错误基线：只接受当前尚未产生提交的分支，不接受任意未来分支。
- 有提交仓库错误放行：保持既有基线存在校验。
- Git 能力被误认为已启动：worktree 创建前校验提交，降级原因写入 assigned 状态的
  execution.activity，不生成 branch/worktree 字段。
- 并发更新覆盖：只在任务仍为 agent/assigned 时写入降级说明。
- 兼容策略：不改存储结构，首次用户提交后重试指派即可恢复 Git 能力。
- 回滚：恢复本次源码并重建插件；已登记看板、任务、已有分支与工作区均保留。

## 里程碑与并行边界

1. 核心代理：git.ts 与 git.test.ts；实现身份/登记/执行条件及临时 Git 用例。
2. 契约/UI 代理：mcp handlers/register/test 与四个 UI 说明文件；识别 unborn 基线。
3. 文档代理：README、WORKFLOW、extension README 和英文技能。
4. 主代理：engine 降级说明、widget 契约、verify-plugin、版本、整合验证与留档。

依赖实现完成后串行构建；不会由多个负责人写同一文件。

## 验证方式与验收标准

- pnpm build/test/smoke、verify:git、verify:twoproc、verify:plugin。
- UI 类型检查与构建；本次只修改说明文本，宿主面板显示另行记录。
- 每条后台验证设置 60 秒进程组硬超时；使用临时数据和临时 Git 仓库。
- 空仓库打开成功、相同身份复用、任务归属正确；错误分支和非 Git 目录仍拒绝。
- 没有首次提交时不创建工作区、不生成提交；临时仓库用户式首次提交后恢复执行。
- 实际结果：52 项单元测试、核心构建、stdio 冒烟、Git 集成、双进程、插件协议、
  UI 类型检查与构建均通过，最后的插件重建及协议复验通过。
- 独立审查发现并修复仓库路径失效时的静默降级提示遗漏及目录检测说明遗漏。
- 当前项目真实 MCP 打开仍返回旧无提交校验错误；已安装文件含新校验代码，但当前
  会话运行的服务未刷新。原生宿主显示验收需重新加载服务后完成，不计为通过。
