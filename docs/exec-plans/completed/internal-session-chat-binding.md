## 最新目标与范围

用户在实施中明确收敛要求：内部 sessionId 与绑定会话字段分别保留，只处理 UI 的显示优先级，不需要调整内部 ID 的生成逻辑。
因此本次初始新增的创建/补齐逻辑和对应 core/MCP/scripts 断言已全部撤回，保留同文件中其它会话的删除功能改动。

- 包含：详情优先显示有效 executionBinding.threadId，否则显示现有 execution.sessionId；无真实绑定时标记未绑定，同时保留 pending/uncertain 进度。显示回归、UI 说明和插件版本同步。
- 不包含：内部 ID 生成、批量历史迁移、存储版本和 MCP 契约变化、真实聊天绑定写入或替换、打开会话逻辑、安装用户插件、操作真实任务。

## 显示规则

1. 有有效真实绑定：显示 threadId，不混入内部 sessionId。
2. 未绑定或绑定只有创建中占位值：显示已有内部 sessionId 并标记未绑定，不从它构造聊天 URL。
3. 请求 pending/uncertain 时仍显示进度；本地 ID 不参与运行状态推导。
4. 两字段都没有则显示未绑定，不在渲染/读取时生成或写入任何 ID。
