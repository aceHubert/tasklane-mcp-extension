## 目标

任务默认保持人工标识，只有用户明确通过 Run Codex/继续执行创建有效的持久执行请求，才在同一事务内标记为 Agent。
移除界面上独立的 Assign to Human/Agent 以及创建后自动指派选项，避免纯标识操作被当作执行命令。

## 范围

- 包含：核心执行请求事务自动设置 assignee、卡片/详情/新建表单移除手动指派、回归测试、使用说明与插件构建。
- 不包含：修改真实会话打开、执行状态机、旧任务迁移、停止能力、移除 MCP task_assign 契约、真实任务或会话操作。

## 背景

当前 task_execution_request 已持久化用户执行意图，但 assignee 保持原值，UI 则另外提供无执行副作用的指派按钮。
两者割裂导致执行请求与人工/Agent 标识不一致。[原生契约](../../native-execution-contract.md)与 UI 操作层共用核心写入规则。

## 风险和兼容

- assignee=agent 仅表示用户已请求 Agent 处理，不证明运行。执行态仍从 starting 等待真实 running 回执，不能设置 startedAt。
- 参数错误、错误看板、归档、执行忙或未完成宿主门控均不能改变标识；新请求持久化、Agent 标识和请求事件原子提交。
- 明确投递拒绝/结果未知仍保留已记录的 Agent 执行意图，错误独立展示；失败或完成不自动切回人工。
- 幂等重放不改写后续编辑或手动 MCP 指派，不追加指派事件。MCP task_assign 为已有 Agent 调用保留，仍不启停执行。
- 无存储版本升级、无真实数据回迁。回滚只还原本次源码，不删除请求、聊天、分支或工作区。
