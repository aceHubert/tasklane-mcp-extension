## 设计动机

- 流转校验与 sessionId 落盘都基于同一原则：**校验与写必须在同一事务内基于磁盘最新状态**，进程内 `taskLocks` 无法约束另一个 MCP 进程。
- worktree 复用与 diff 前都走 `assertWorktreeMatches`：目录"存在"不等于"绑定正确"，宁可明确报错/降级也不读错仓库的数据。
- bridge 修复遵循"薄桥不崩"：任何畸形输入返回 4xx/错误响应，进程存活优先；子进程流错误只记日志。
- UI 连接生命周期与数据刷新解耦：连接只随 `client` 建立，刷新函数经 ref 引用，从根上消除 effect 重跑叠加连接。
- 错误态契约两端对齐：服务端错误结果自带 widget 标识，客户端既有解析即可渲染 project-error；不改客户端判定逻辑，避免把普通板面工具的 isError 结果误判为打开失败。
- 无持久化格式与 MCP 契约变更，不需要迁移与回滚特殊处理；插件产物可通过 `pnpm build:plugin` 随时重建。
