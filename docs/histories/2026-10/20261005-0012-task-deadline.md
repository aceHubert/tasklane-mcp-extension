### 变更概览

**影响范围**：`packages/core/`、`mcp/`、`ui/`、`README.md`、`docs/exec-plans/`。

**主要操作**：

- **core 模型**：`WorkItem` 新增可空 `deadline?: string`（UTC ISO 语义注释）；新增 `normalizeDeadline` 校验辅助（无效日期抛 `VALIDATION`，成功规范化为 `toISOString()`）。
- **core 写入路径**：`engine.createTask` 接受可选 `deadline` 并规范化；`engine.updateTask` 支持 `deadline` 字符串设置 / `null` 清除 / 不传不动。
- **core 排序**：`board-store.listTasks` 排序由纯 ID 升序改为 `compareTasks` 三分组——未完成任务排 done 之前；未完成内部有 deadline 按 deadline 升序在前、无 deadline 按 ID 序靠后；done 保持 ID 序。`normalizeV4` 对 `deadline` 只做类型校验（与 description 同级），坏值不阻断看板加载。
- **MCP 契约**：`task_create` 增加可选 `deadline`（zod refine 校验可被 `Date` 解析）；`task_update` 增加 `deadline`（nullable，`null` 清除）；工具 description 与 handlers 参数类型同步。
- **UI**：`ui/src/mcp/types.ts` 新增 `toLocalInputValue` / `formatDeadline` / `deadlineOverdue`；`NewTaskForm` 增加可选 `datetime-local` 截止时间输入；`TaskDetail` 在状态/优先级行下方增加 deadline 编辑行（blur 保存纳入脏字段机制）与「清除」按钮（提交 `null`）；`TaskCard` 未完成任务显示截止 chip（`ClockIcon` + 本地短格式），过期标红；i18n 中英新增 `form.deadline`、`detail.fieldDeadline`、`detail.deadlineClear`、`card.overdue` 等键；`styles.css` 新增 `.deadline-row` 与 `.deadline-chip.overdue` 样式。
- **测试**：core 新增 deadline 创建规范化/更新/清除/非法拒绝用例、列表三分组排序用例、deadline 落盘读回用例；mcp 新增 handler 级与 InMemoryTransport schema 级 deadline 契约用例；更新受「done 排后」影响的全量列表顺序断言（store.test.ts archive 过滤测试）。

### 设计动机

排序放在 core 层 `listTasks` 而非 UI：业务规则集中在核心层，Agent 与 UI 共用同一 MCP 排序语义，宽窄两个视图自动继承。deadline 统一规范化为 UTC ISO 存储，保证字典序即时间序、排序可直接做字符串比较；UI 输入输出在本地时区转换。清除语义用显式 `deadline: null`，与「不传」区分，避免歧义。`normalizeV4` 只做类型校验（不做严格日期解析），坏值不阻断整个看板加载，严格校验只发生在写入路径。存储 v5 对可选字段向后兼容，无需版本迁移；归档任务共享同一模型，`archive: 'active'` 不读冷文件，排序改动不影响归档区。回滚方式：改动为纯增量字段与排序 comparator，回滚代码即可；已写入的 deadline 字段在旧代码下被忽略，无破坏性。
