# 仓库变更历史记录规范

`docs/histories/` 记录已完成的仓库改动，包括代码、配置及配套文档。纯问答或调研无需记录；仅新增或更新调研、评估、报告、执行计划及其模板，也无需额外记录。

## 基本要求

- 每个完成的改动任务对应一份历史记录；同一任务跨多轮推进时维护同一文件。
- 用户诉求可以压缩，但应保留关键目标和约束。
- 不写入敏感信息、本机绝对路径、凭证或原始日志细节；路径使用仓库相对路径。
- 如实填写执行上下文；无法确认的模型或运行环境写“未知”，不得推测。
- 记录实际结果、未覆盖场景和阻塞原因，不能把待执行的检查写成通过。

## 目录与命名

- 目录：`docs/histories/YYYY-MM/`，按需创建月份目录。
- 文件名：`YYYYMMDD-HHmm-task-slug.md`，时间与记录正文一致，并注明时区；本项目默认使用 `Asia/Shanghai`（`+0800`）。
- 模板：[histories/template.md](histories/template.md)。
- 示例：`docs/histories/2026-10/20261003-1300-board-store-lock-fix.md`。

## 应该写什么

- 原始诉求或压缩后的脱敏版本。
- 执行上下文、主要代码与文档改动及关联执行计划。
- 设计动机、关键决策及受影响文件。
- 验证命令、结果和未覆盖场景；UI 记录视口与运行模式，Git/存储验证说明临时环境。
- 本次任务的变更统计及统计口径。

## Git 用户与变更统计

使用以下只读命令取得真实身份和分支；未配置时如实注明，不为填写记录修改 Git 配置。

```bash
git config user.name
git config user.email
git symbolic-ref --short HEAD
```

Git 用户写为 `姓名 <邮箱>`；多位作者接力时可列多行。分离 HEAD 时记录 `git rev-parse --short HEAD` 的结果及分离状态；尚无提交时不能假设 `HEAD` 可用于差异基线。

已提交的任务以任务涉及的提交为范围：

```bash
# 总计
git diff --shortstat <base>..HEAD
# 逐文件行数
git diff --numstat <base>..HEAD
```

`<base>` 是任务开始前的提交；单次提交且存在父提交时可用 `HEAD~1`。需要合并基点时通过 `git merge-base HEAD <目标分支>` 确认，不直接假设目标分支最新提交就是基线。存在其他任务的提交时，进一步限定文件或使用任务开始前快照，说明统计边界。

尚未提交时，已有有效 `HEAD` 的已跟踪文件可用 `git diff HEAD -- <本次任务文件>`，分别添加 `--shortstat` 和 `--numstat`。它不包含未跟踪文件，且会包含任务开始前已有的改动；这两种情况使用任务前快照对比，新增文件与 `/dev/null` 对比：

```bash
git diff --no-index --shortstat /dev/null <新增文件>
git diff --no-index --numstat /dev/null <新增文件>
```

`--no-index` 返回 1 表示存在差异，并非执行失败。空的 `.gitkeep` 没有行数差异，单独列为新增文件并计入文件数。二进制文件的增删行数写 `bin`。记录所用基线、路径范围及汇总方式，排除任务前已有的代码、图标、设计稿等无关改动。

历史记录自身默认不计入变更统计，避免更新统计时循环变化；在统计口径中注明这一点。
